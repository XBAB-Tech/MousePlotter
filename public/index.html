How to use

MousePlotter is a browser-based version of MouseTester by microe1. Both tools plot mouse report data, especially raw motion counts, against time.

Three useful workflows:

  1. Single swipe. Click and hold, swipe once, then release. This can help test that your mouse tracks correctly at high speeds, and the Δt plot shows your mouse's report interval. Patterns in the x and y counts can sometimes reveal artifacts related to sensor framerate, smoothing, and similar processing.
  2. Continuous reports. First, set your mouse to a high DPI such as 6400. Click and hold, move the mouse in medium-speed circles for as long as you like, then release. This shows how stably your browser receives mouse data (or, when importing a CSV, how stably the logging application received it).
  3. DPI measurement. Place a ruler or a piece of paper with a known horizontal length on your mousepad. Align a visible point on the mouse with the start mark. Press Space, move horizontally without changing the mouse angle, then press Space again. Divide Total X by the number of inches traveled.

Plot navigation. Double-click to reset. Middle-click and drag inside the plot to pan both directions, or on an axis to pan only that direction. Drag a box or scroll over the plot to zoom. Scroll over an axis to zoom only that direction.

What does jitter in the Δt plot mean?

If the Δt plot looks fuzzy, like the example below, the most likely cause is timing jitter in the operating system's data pipeline.

Mouse firmware cannot directly affect the timing of USB reports: that timing is dictated entirely by the USB host controller. Host controllers tend to behave very regularly, with negligible jitter, as long as there is not too much bus activity. Jitter that is not quantized to multiples of 125µs, as in the image above, is therefore typically caused entirely by operating system and CPU behavior.

What mouse firmware can do is decide whether or not to respond to a poll. Ideally, under sufficient motion, firmware responds to every poll. Seeing this clearly requires the fuzz described above to have an amplitude smaller than 125µs. Many people report that disabling CPU C-states helps. Operating system tweaks may help as well, and the browser itself can also be a limiting factor.

Standalone logging utilities

Browsers are ultimately not ideal for logging data with microsecond-level timing precision. For this reason, the GitHub repository includes minimal logging utilities for both Linux and Windows. Follow the instructions there, save a CSV, and import it into MousePlotter for an interactive plot.

You can also use MouseTester itself: MousePlotter is fully compatible with MouseTester CSVs, and vice versa.
